# Changelog

## 0.3.1

- **Changed after closing.** A deal that was closed last time and is still closed now, but whose result flipped (won to lost, or lost to won) or whose amount moved, is listed in a new section: "was won, now lost", "won amount $250,000 → $300,000". Before, it disappeared: a $250K deal won last week and lost this week printed "Closed 0 won and 0 lost" and "Nothing flagged". It is not counted in Closed (deals closed this week); the headline adds "1 deal changed after closing." The dollar bridge is unchanged, since such a deal was never in the open pipeline. Both modes; in stateless mode the status and amount then come from property history, and an amount then that history cannot answer is never reported as an amount change. The demo shows one.
- **A short pipeline change log no longer empties a pipeline.** When a pipeline's change log in HubSpot starts after the comparison date but deals sat in it then, stateless mode reads its stages then from the oldest settings HubSpot kept, and the brief says so in one line, instead of listing every deal in it under Could not rebuild. A Could not rebuild line for a missing stage now says which cause it can see: the pipeline was deleted since, or the stage is missing from that pipeline's settings for that date.
- A deal that existed on the comparison date but whose history holds no stage for that date is listed under Could not rebuild ("HubSpot's history holds no stage for it on Oct 2"), never as New.
- A deal stateless mode could not rebuild that is closed today ends "won now" or "lost now".
- **A Tuesday run by hand no longer becomes next Monday's baseline.** Stored mode compares with the newest snapshot 7 or 8 days old; with none that age, the newest at least 6 days old (as before); else the newest earlier one. Before, a run by hand on Tuesday was 6 days old by Monday and replaced last Monday's snapshot, so Monday-afternoon changes vanished from the weekly brief.
- **Slack, when the brief is too long.** The Slack copy first shows fewer deals per section (5, then 3, then 1) so every group and section keeps its heading, and says so; only then is it cut. The note names the saved brief's file name (never a local path), or in stateless mode without `--out` says to run with `--out FILE`. Before, it always pointed to "the saved file", which stateless mode never writes unless asked.
- **Exchange-rate moves are labelled.** Snapshots also store each deal's own currency (`deal_currency_code`) and its amount in that currency. On a multi-currency portal, an Amount changed (or Changed after closing) line whose home-currency amount moved while the deal's own amount and currency did not ends "(exchange rate)", and a closed deal moved only by the rate is not listed under Changed after closing at all (otherwise every older foreign-currency deal would show every week). In the first comparison after upgrading, last week's snapshot has no currency fields, so an amount change on a deal in another currency says "(currency unknown last week)". The README no longer says stored mode simply works on multi-currency portals: HubSpot's conversion follows its current rate. Not yet checked on a real multi-currency portal.
- **Two reps with one name stay two.** `--group-by owner` groups by HubSpot owner id instead of the display name, which merged reps who share a name. Two owners with the same name are told apart everywhere the brief names them: "Dana Ruiz (dana@example.com)", or "(owner 102)" when the email does not tell them apart. Snapshots now store each deal's `owner_id`; snapshots written before still load, and a deal from one joins the rep who has that name today.
- **Pinning, stated honestly.** A git tag can be moved by whoever controls the repository, so the README no longer says the pinned tag guarantees nothing else runs with your token; it says how to pin the commit SHA the tag points at (`git ls-remote ... refs/tags/v0.3.1`), and the Action says the same in a comment. The Action pins `actions/setup-node` by commit SHA (`# v4.4.0`).
- A deal listed twice in HubSpot's recycle bin is read once. Before, stateless mode stopped with exit 2 every run, since the batch read returned fewer deals than it was asked for.
- The stderr note for a stateless run with no `--out` and no Slack is now true when standard output is piped or redirected to a file: "This run kept no copy of the brief of its own".
- stderr carries counts only, never a dollar amount, so a public GitHub Action's log shows no pipeline money; that includes the error if the dollar bridge ever fails to add up, which no longer prints cent figures. The brief itself is unchanged.
- Short dollar amounts: $999,500 prints as $1.00M (never $1,000K), a billion as $1.00B (never $1000.00M), and an amount that rounds to zero as $0 (never -$0). The headline's change is worked from the bridge in cents, so it can no longer say "down $0" when nothing moved.
- **Atomic writes.** Snapshots and briefs are written to a temp file in the same folder and renamed into place, so a write that fails part way (a full disk) never leaves a half-written file, and the message "No snapshot or brief was written" is true. A file that already exists keeps its permissions, as before.
- The README says how fast stored snapshots grow (about half a kilobyte per deal per run) and how to prune them by hand. The tool still deletes nothing.
- A grouped brief with nothing in any group ends with its "Nothing flagged" line, like a flat one.
- The stateless stderr line names the comparison date the brief uses (the local date), then the exact instant in UTC.
- `help` lists all three scopes, including `settings.currencies.read` for stateless mode.
- **The npx command the tool prints is pinned.** Help, the missing-token hint and the demo's closing line show `npx github:derrtaderr/monday-pipeline-brief#v0.3.1` to npx users, built from the package version. Before, they showed the unpinned command.

## 0.3.0

- **Stateless mode.** `run --since 7d` (1d to 90d), or `run --as-of 2026-10-01T09:00:00Z`, or `MONDAY_BRIEF_SINCE=7d`, rebuilds your pipeline as it stood then from HubSpot's property history and compares it with today. The first run gives the full brief, and nothing is kept between runs: no snapshot (neither the rebuilt one nor today's), no `run.log`; only `--out` writes a file. Stored snapshots stay the default and work exactly as before.
- **Could not rebuild.** HubSpot keeps the newest 20 versions of a property. A deal changed more than 20 times since the comparison date in its stage, pipeline, amount or close date, or a deal two records were merged into since then, is listed under "Could not rebuild as of <date>" with what is unknown and the merged record ids, and on a "Could not rebuild" bridge line, so the bridge still adds up to today's open total. A deal whose state then is known (open with a known amount, or closed) still counts: the start line reads "$215,000 ($206,000 rebuilt + $9,000 from 1 deal only partly rebuilt)", and such a deal gone today leaves through Removed from HubSpot. Otherwise it is left out of the start total, and the headline says what is left out, counting each merged record as its sources: "(the Oct 2 total leaves out 2 deals merged since then and 1 deal whose state then could not be rebuilt)".
- **Push count.** In stateless mode a slipped deal whose close date moved later two or more times since the comparison date says so: "(+46 days, pushed 2 times)". Pull-ins, cleared dates and the date HubSpot stamps on close do not count.
- **Pinned release.** The README quickstart and the GitHub Action run `npx github:derrtaderr/monday-pipeline-brief#v0.3.0`, so a later change to this repository never runs with your HubSpot token until you change the tag. The README notes that GitHub turns off scheduled workflows in a public repository after 60 days with no activity.
- **One currency only, for now.** Stateless mode reads the portal's exchange rates first and refuses a portal with more than one currency, or a token without the new `settings.currencies.read` scope, with exit 5 and a message. Stored mode does not need the scope.
- **Never a guessed status.** A deal whose stage on the comparison date is missing from the pipeline settings HubSpot kept for that date (a deleted pipeline or stage, or a pipeline change log that does not reach back that far) is listed under Could not rebuild and left out of the start total; it is never counted as open, won or lost then.
- **Partial reads never render.** A batch read of deleted deals that comes back partial (HTTP 207 with errors, or fewer deals than asked) stops the run with exit 2 and no brief.
- `--as-of` rejects a date that does not exist (2026-09-31). Run without a terminal and without `--out` or Slack, stateless mode says on stderr that the brief went nowhere else.
- **A GitHub Action with no state**, `examples/github-action.yml`, runs stateless mode every Monday and posts to Slack. It fails at once when the `SLACK_WEBHOOK_URL` secret is missing.
- The README quickstart leads with stateless mode; scheduling stored mode with cron or launchd moved to an appendix. A new README section lists what stateless mode cannot see: merges, more than 20 changes, restored deals, permanently deleted deals, deleted pipelines' stage names, deals deleted moments before the run, and multi-currency portals.

## 0.2.1

- **Raw HTML in HubSpot text stays text.** In the Markdown brief, a `<` that would start an HTML tag, comment or autolink (a `<` followed by a letter, `/`, `!` or `?`) is written as `&lt;`, and an `&` that would start a character reference (such as `&lt;` or `&#60;`) is written as `&amp;`, in deal names, owner names, stage and pipeline labels, group headings and the labels of deal links. Before, a name such as `<a href="...">Click</a>` or `<https://...>` became a live link in Markdown viewers that render HTML (GitHub, Obsidian, VS Code preview). Everything else prints as typed: "Johnson & Johnson", "R&D", "A < B" and "Q&A <3" are unchanged. Slack still gets every `&`, `<` and `>` escaped, once.
- **Closed in another pipeline.** A deal that went from an open stage straight to a closed stage of another pipeline reads "won, moved from Sales Pipeline to Onboarding" on its Closed line, and shows under both pipelines with `--group-by pipeline`. Before, it read only "won". The bridge is unchanged.
- **Same-size deals are not large.** When every open deal above $0 has the same amount and there are more of them than the 10% limit allows, no deal is a large deal. Before, the deals with the lowest record ids were tagged "large deal". Same-size deals that all fit within the limit (a lone deal, or two $50K deals among twenty-eight $0 deals) are still large, and a partial tie at the cut-off (some smaller deals exist) still takes the lowest record ids.
- **Pipeline groups follow the pipeline, not its name.** With `--group-by pipeline`, groups are keyed by HubSpot pipeline id and headed with today's name. A renamed pipeline no longer shows a second, phantom heading under its old name; a pipeline that is gone keeps its last name; two pipelines with the same name no longer merge, and each heading carries the pipeline id after the name. A move or a close between pipelines that share a name puts the id after each name on its line too, in every mode.
- `demo --dir` is a usage error (exit 1) instead of being silently ignored; `demo` reads its bundled sample data and writes no snapshot.
- **Changed stage.** A deal that left a stage which has since been deleted in HubSpot is listed under a new "Changed stage" section, old stage to new, with no back or forward. Before, its direction was read from two different stage orders (last week's and today's), which could be wrong or, after a reorder, print nothing at all.
- The demo shows a Changed stage line (a Renewals stage deleted between the two weeks) and a deal closed straight into another pipeline.
- Slack formatting marks typed into a HubSpot name (`*bold*`, `_italic_`, `~strike~`, backticks) still format in Slack; Slack has no escape for them. README Limitations says so.

## 0.2.0

- **Stage reorders are no longer stage moves.** A deal moved back or forward only when its stage changed within the same pipeline. Before, reordering the stages in a pipeline made deals that never moved read as moved. The direction of a real move is judged in today's stage order: snapshots now store every pipeline's full stage order, so a move out of a stage that is now empty or was itself moved reads the right way. When today's stage order does not list a stage (deleted), or the snapshot has no stored order (written by 0.1), the deals' own stage orders are used instead.
- **How the open pipeline changed.** A short reconciliation from last week's open total to this week's: new deals, reopened, amount increases and decreases, won, lost, and deals HubSpot no longer returns. It is worked in cents and checked before the brief is written, so it always adds up; the printed lines use exact dollars. New sections name the deals behind it: Amount changed (old to new amount), Reopened, Removed from HubSpot.
- **Moved to another pipeline.** A deal that moved pipeline gets its own line, old pipeline and stage to new, in the flat brief and under both pipelines when grouped by pipeline.
- **Close date passed.** Open deals whose close date is before the day of the brief get their own section and flag, on the first run too.
- **Look at these first** also takes a deal with one warning sign when it is a large deal (by default the largest open deals, at most 10% of them and at least one, with ties at the cut-off left out; `--large-deal AMOUNT` or `MONDAY_BRIEF_LARGE_DEAL`, or `off`) or when its close date slipped into a later calendar quarter. Each line says why it is there.
- **Deal links.** Each deal's name links to its HubSpot record, in Markdown and in Slack. Snapshots now store the record URL; 0.1 snapshots still load and their deals show a plain name.
- **Grouping.** `--group-by owner` or `--group-by pipeline` (or `MONDAY_BRIEF_GROUP_BY`) gives each rep or pipeline its own heading and sections. The default stays one list.
- Every piece of text that comes from HubSpot (deal names, owner names, stage labels, pipeline labels) is escaped wherever the brief prints it, flat or grouped, in Markdown and in Slack, so none of it can become link markup, break a line, or mention a Slack channel. The only links the brief writes are the deal record links. A bare web address typed into a HubSpot name stays plain text in the brief, though Slack and GitHub may still turn it into a clickable address when they display it.
- `demo` ends with one line on stderr saying it was sample data and what to run next.
- A deal id that appears twice (in a HubSpot listing or an old snapshot) is kept once.
- README opens on the outcome and no longer says HubSpot stores only current state.

## 0.1.1

- **Stale check on portals with little logged activity.** A deal with no logged activity is now flagged only once it is 14 or more days old, judged by its creation date (`createdate`), and the brief says "no activity logged since it was created Sep 20". Before, every deal with no logged activity was flagged, including deals created that day, and those flags also filled "Look at these first". An empty Next step is still flagged at any age.
- **Service keys.** New HubSpot accounts offer service keys instead of private apps. A service key works unchanged; the quickstart now leads with it and keeps a short private app path for older accounts. Messages now say "service key or private app token".
- Snapshots store each deal's creation date. Snapshots written by 0.1.0 still load as the comparison baseline.
- Run on one real HubSpot portal (custom pipeline, service key, test data).

## 0.1.0

- First release. Weekly HubSpot deal snapshots on your own disk, compared week over week into a markdown brief: open pipeline total and change, won and lost, slipped close dates, stage moves, no next step or no recent activity, new deals, and the deals with more than one warning. Optional Slack post. Zero dependencies.
